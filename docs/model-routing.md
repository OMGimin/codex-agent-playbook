# 모델 배정과 환경 조건

이 저장소는 작성자의 현재 정책을 배포합니다. 아래 모델 ID와 native `spawn_agent` 호출 조건은 작성 환경에서 관찰한 계약이며, 모든 Codex 제품·계정·버전의 공개 API 계약이 아닙니다.

| 담당 | 현재 프로필 | 책임 |
|---|---|---|
| 최상위 총괄 1명 | `gpt-6-astra`, `high` | 기획, 분해, 통합, 근거 확인, 보고, 필요한 직접 작업 |
| 실행·조사·검토·자문 | `gpt-6-sol` 또는 `gpt-6-luna` | 범위가 정해진 산출물과 검증 근거 반환 |

복잡한 구현·분석에는 Sol, 작고 명확한 확인에는 Luna를 고려합니다. 이는 작업 배정 원칙이며 모델별 우열이나 비용 절감의 실측 결과가 아닙니다. 추론 강도는 호스트가 지원하는 값만 사용합니다.

생성 시 모델을 명시합니다. 작성 환경의 `spawn_agent`에서는 모델 오버라이드와 함께 `fork_turns: "none"` 또는 지원되는 양의 턴 수를 사용합니다. 다른 환경에서는 도구 스키마를 먼저 확인하며 이 인자를 그대로 가정하지 않습니다. [실제 스킬의 배정 규칙](../skills/work-orchestrator/references/model-routing.md)을 읽으세요.

명시한 모델 요청의 수락과 별도의 런타임 모델 확인은 구분합니다. 실행 모델 정보가 없다는 이유만으로 수락된 요청을 중단하지 않지만, 실제 모델을 별도로 확인했다고 주장하지도 않습니다. 수락 여부가 불명확하면 상태부터 확인합니다. 미지원·거부·제한 위반을 다른 모델의 무단 사용으로 해결하지 않습니다.

다른 모델 정책으로 배포하려면 프로젝트 소유자가 먼저 선택하고 `templates/AGENTS.md` 15번, work-orchestrator와 model-routing 참조, requesting-code-review, decision-council, 설명 문서를 함께 수정해야 합니다. 기존 권한·예산 제한을 넓히는 변경은 명시적인 승인을 받습니다. 지원 모델이 없으면 원래 정책을 몰래 바꾸지 말고 직접 수행 가능한 범위를 보고합니다.

서브에이전트는 현재 요청의 하위 작업이고, 사이드바의 별도 사용자 작업은 별개입니다. 이 설정만으로 별도 작업을 생성하거나 현재 총괄 모델을 바꾸지는 않습니다.
