# 백엔드 기능 구현 요청 예시

이 문서는 가상의 사용 예시이며 실행 결과가 아닙니다.

```text
$work-orchestrator 기존 주문 API에 중복 요청 방지를 추가해줘.
현재 코드와 API 계약을 먼저 확인하고, 기존 응답 호환성을 유지해줘.
구현과 관련 테스트까지 진행하되 외부 배포와 운영 DB 변경은 제외해.
독립적으로 진행할 이점이 있을 때만 하위 에이전트를 사용해.
```

총괄은 기존 계약과 트랜잭션 경계를 확인하고 완료 기준을 정합니다. 구현 담당과 독립적인 테스트 설계·검토 담당의 파일 소유권을 나눌 수 있습니다. 구현 전 브랜치 보호와 작업트리 동의 조건을 확인합니다. 작은 변경이면 직접 처리합니다.

완료 증거에는 동일 키 재요청, 서로 다른 요청의 키 충돌, 동시 요청 등 실제 요구사항에 맞는 검증을 포함합니다. 구현 담당의 보고만으로 성공을 선언하지 않고 실제 변경과 테스트 출력을 확인합니다. 운영 반영은 이 요청의 완료 조건에 포함되지 않습니다.
